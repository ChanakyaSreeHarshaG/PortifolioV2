SQL Interview Cheat Sheet

8 Essential SQL Patterns

SQL is the highest-ROI skill in a Data Analyst or Data Engineer interview. Almost every live coding question you will encounter is one of these 8 patterns wearing a different business scenario.

Company-specific questions from Capgemini, Deloitte, Infosys, etc.
01Running Totals

Cumulative sum as you move through ordered rows — each row's total includes everything before it.

SUM(x) OVER (ORDER BY d)

Ties in ORDER BY get summed together in one step unless you force ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW.

02Deduplication

Keep exactly one row per key, drop the rest — rank duplicates, then filter to rank 1.

ROW_NUMBER() OVER (PARTITION BY k ORDER BY tiebreak)

No stable tiebreaker means the survivor is arbitrary — add the primary key as a final sort column.

03Gaps & Islands

Find streaks of consecutive values, or the missing values between them, in an ordered sequence.

d - ROW_NUMBER() OVER (ORDER BY d) AS grp

Only works on genuinely sequential data — truncate timestamps to the grain you care about first.

04Join Patterns

The join type is the business question: what to do when a match is missing.

LEFT JOIN b ON a.k=b.k WHERE b.k IS NULL

Filtering a LEFT JOIN in WHERE silently turns it into an INNER JOIN — filter the right table in ON instead.

05Aggregations

Collapse many rows into one summary row per group — the backbone of most dashboard metrics.

GROUP BY g HAVING SUM(x) > n

WHERE filters rows before grouping; HAVING filters after. You can't put an aggregate in WHERE.

06Subqueries

A query nested inside another — correlated ones re-run per outer row, non-correlated run once.

WHERE salary > (SELECT AVG(salary) WHERE dept=e.dept)

NOT IN silently returns zero rows if the subquery list contains a NULL — prefer NOT EXISTS.

07CTE

Name each intermediate step so a complex query reads top-to-bottom instead of inside-out.

WITH step1 AS (...), step2 AS (...) SELECT ...

A CTE isn't automatically materialized or cached — referencing it twice may recompute it, engine-dependent.

08Ranking / Top-N

Top N rows per group — something a plain GROUP BY can't return, since it only gives an aggregate.

RANK() OVER (PARTITION BY g ORDER BY x DESC)

Can't filter the rank alias in the same SELECT that defines it — wrap it in a CTE, then filter the outer query.
